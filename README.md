# protein-eval-skill

A Codex skill for audited batch evaluation of protein and peptide complex
predictions against annotated reference structures. It accepts single-model
PDB or mmCIF files from any prediction tool, including AlphaFold 3 and Boltz.
The workflow requires an annotated protein or peptide target and at least one
protein or peptide binder group. Targets and binder groups can each span
multiple chains.

## What it evaluates

- **Folding** includes target and binder self-aligned backbone RMSDs, target-only
  and binder-only all-atom lDDT, and Cα chirality accuracy.
- **Docking** includes target–binder DockQ, L-RMSD, iRMSD, and macro iLDDT.
  L-RMSD is binder N/CA/C/O RMSD after jointly fitting all annotated target
  chains without refitting the binder.
- **Supplemental metrics** include global scored-complex lDDT, target–binder
  DockQ-wave, and micro iLDDT.

Every lDDT and iLDDT summary reports scores with OpenStructure stereochemistry
checks on and off. The runner scores the annotated target and binder chains
and records the chain mapping, coverage, and unavailable metrics. Small-molecule
ligand scoring requires a separate workflow.

## Install from GitHub

Install the standalone repository with Codex's skill installer:

```bash
python ~/.codex/skills/.system/skill-installer/scripts/install-skill-from-github.py \
  --repo hsicat/protein-eval-skill \
  --path . \
  --name protein-eval-skill
```

The skill becomes available as `$protein-eval-skill` on the next Codex turn.

## Runtime requirements

- Conda environment `urop` with Python, NumPy, and Gemmi.
- Conda environment `ost212` with OpenStructure 2.12.0.
- An evaluation directory with persistent biological-role and chain-mapping
  annotations as described in `references/annotations.md`.

The runner expects these environment names and uses the bundled chirality scripts.
Create both Conda environments from the repository root:

```bash
conda env create --file environment-urop.yml
conda env create --file environment-ost212.yml
```

Verify their versions:

```bash
conda run -n urop python -c \
  'import gemmi, numpy; print(gemmi.__version__, numpy.__version__)'
conda run -n ost212 ost --version
```

The environment files pin Gemmi 0.7.5, NumPy 1.26.4, and OpenStructure 2.12.0.
The dependency solves were dry-run verified for `osx-arm64` and `linux-64`.

## Expected evaluation directory structure

The runner accepts an evaluation directory with this layout. Prediction files
may be nested to any depth below `predicted/` and must use a `.cif`, `.mmcif`,
or `.pdb` extension.

```text
project/
|-- evaluation/
|   |-- predicted/
|   |   `-- method-name/
|   |       `-- SAMPLE_ID/
|   |           `-- model_0.cif
|   |-- annotations/
|   |   `-- samples.json
|   `-- results/                         Generated by --execute
|       |-- batch_summary.csv
|       |-- method_summary.json
|       |-- method_summary.md
|       |-- batches/
|       |   `-- <batch-fingerprint>/
|       |       `-- run_manifest.json
|       `-- method-name/
|           `-- SAMPLE_ID/
|               `-- model_0.cif/
|                   `-- runs/
|                       `-- <fingerprint>/
|                           |-- summary.json
|                           |-- ost_scores.json
|                           |-- role_metrics.json
|                           |-- binder_rmsd.json
|                           `-- chirality/
|-- GT/
|   `-- SAMPLE_ID.cif                   Exact reference structure or assembly
```

`annotations/samples.json` maps each discovered prediction to its reference,
biological roles, and chain mapping. Paths in that file are relative to the
`evaluation/` directory, so the example reference path is
`../GT/SAMPLE_ID.cif` and the prediction key is exactly
`predicted/method-name/SAMPLE_ID/model_0.cif`. Each scored prediction needs
an exact reference assembly, chain roles, and a one-to-one reference-to-model
chain mapping. The schema supports mmCIF label IDs and author chain IDs.
See [the annotation schema](references/annotations.md).

For a single-sample evaluation, place one structure below `predicted/` and
define one matching sample and prediction entry in `samples.json`. If multiple
structure files are present, every discovered prediction must be annotated or
the audit will be blocked.

## Use

```text
Use $protein-eval-skill to evaluate <evaluation-directory>. The native structures are stored in <native-directory>. Audit the files first, ask me about unresolved chain roles or mappings, then run the batch.
```

To run directly from the skill directory, audit first:

```bash
conda run -n urop python scripts/batch_evaluate.py /path/to/evaluation
```

Resolve any ambiguous sample matches, assemblies, chain roles, or mappings.
Once the audit reports `READY`, execute:

```bash
conda run -n urop python scripts/batch_evaluate.py /path/to/evaluation --execute
```

Use `--annotations` to choose a different annotation file, and `--method-name`
to group the results of a single method whose prediction folders are organized
by seed. The [archived benchmark mappings](ref_mapping_1127/README.md) are
optional and intended for the exact corresponding inputs.

## Results and thresholds

The batch writes a per-binder CSV, per-prediction JSON and diagnostics, and
three all-seed summary tables in `results/method_summary.md` and
`results/method_summary.json`. Method summaries average available binder
groups or interfaces within a prediction before aggregating predictions.
Metric-specific oracle summaries are a separate analysis. Unavailable values
are shown as NA, including checks-off scores when reading older outputs.

Chirality uses the inclusive **≥15°** cutoff and reports passed / assessable
residues for All (D+L), D-only, and L-only. The default scores the annotated
`chirality_chains`. Use `--chirality-scope whole-example` to score all
annotated target and binder chains.

The default success cutoffs are strict **RMSD < 2 Å** for target and binder
self-aligned backbone RMSD and L-RMSD, and strict **DockQ > 0.23** per
target–binder interface. Use the following options to override them:

- `--target-self-aligned-rmsd-threshold-angstrom`
- `--binder-self-aligned-rmsd-threshold-angstrom`
- `--binder-rmsd-threshold-angstrom` for L-RMSD
- `--dockq-threshold`

To apply a different DockQ cutoff to an existing batch CSV, use
`--dockq-threshold VALUE` with `scripts/summarize_batch_metrics.py`. It
recomputes success from the saved interface scores. Matching successful scoring
runs can be reused. Pass `--resume-incomplete` to retry an incomplete run in a
fresh attempt directory. See [outputs and aggregation](references/outputs.md).

For figures, use the [protein-eval-graph companion skill](https://github.com/hsicat/protein-eval-graph).
