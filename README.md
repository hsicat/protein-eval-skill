# protein-eval-skill

A Codex skill for audited batch evaluation of Boltz protein/peptide complex
predictions against annotated ground truth. It combines OpenStructure scores,
target-aligned and self-aligned binder RMSDs, and residue chirality metrics.

## Features
- Evaluating protein structure predictions in batch with the following metrics
  - **Folding**: Target and binder self-aligned backbone RMSD, separate
    target-only and binder-only all-atom lDDT, chirality, and independent
    RMSD threshold success rates
  - **Docking**: Target-binder DockQ and per-interface success, target-aligned
    binder backbone RMSD, target-binder iRMSD and iLDDT
- Auditing explicit biological-role annotations and reference-to-prediction
  chain mappings before evaluation.
- Support multi-chain target and binder. Target alignment is done with all annotated target chains.


## Install from GitHub

Install the standalone repository with Codex's skill installer:

```bash
python ~/.codex/skills/.system/skill-installer/scripts/install-skill-from-github.py \
  --repo hsicat/protein-eval-skill \
  --path . \
  --name protein-eval-skill
```

The skill becomes available as `$protein-eval-skill` on the next Codex turn.

## Runtime requirements

- Conda environment `urop` with Python, NumPy, and Gemmi.
- Conda environment `ost212` with OpenStructure 2.12.0.
- An evaluation directory with persistent biological-role and chain-mapping
  annotations as described in `references/annotations.md`.

The environment names are currently fixed in the runner. The chirality script
and its companion module are bundled under `scripts/` and installed with the
skill. The runner uses the bundled script by default; `--chirality-script` is
available only when an explicitly inspected replacement is needed.

## Expected evaluation directory structure

The runner accepts an evaluation directory with this layout. Prediction files
may be nested to any depth below `predicted/` and must use a `.cif`, `.mmcif`,
or `.pdb` extension.

```text
project/
|-- evaluation/
|   |-- predicted/
|   |   `-- method-name/
|   |       `-- SAMPLE_ID/
|   |           `-- model_0.cif
|   |-- annotations/
|   |   `-- samples.json
|   `-- results/                         Generated by --execute
|       |-- batch_summary.csv
|       |-- batches/
|       |   `-- <batch-fingerprint>/
|       |       `-- run_manifest.json
|       `-- method-name/
|           `-- SAMPLE_ID/
|               `-- model_0.cif/
|                   `-- runs/
|                       `-- <fingerprint>/
|                           |-- summary.json
|                           |-- ost_scores.json
|                           |-- role_metrics.json
|                           |-- binder_rmsd.json
|                           `-- chirality/
|-- GT/
|   `-- SAMPLE_ID.cif                   Exact reference structure or assembly
```

`annotations/samples.json` maps each discovered prediction to its reference,
biological roles, and chain mapping. Paths in that file are relative to the
`evaluation/` directory, so the example reference path is
`../GT/SAMPLE_ID.cif` and the prediction key is exactly
`predicted/method-name/SAMPLE_ID/model_0.cif`. See
[`references/annotations.md`](references/annotations.md) for the complete
schema.

For a single-sample evaluation, place one structure below `predicted/` and
define one matching sample and prediction entry in `samples.json`. If multiple
structure files are present, every discovered prediction must be annotated or
the audit will be blocked.

Create both runtime environments from the included portable specifications:

```bash
conda env create --file environment-urop.yml
conda env create --file environment-ost212.yml
```

Verify them:

```bash
conda run -n urop python -c \
  'import gemmi, numpy; print(gemmi.__version__, numpy.__version__)'
conda run -n ost212 ost --version
```

Expected versions are Gemmi 0.7.5, NumPy 1.26.4, and OpenStructure 2.12.0.
The files intentionally contain only the packages required by this skill rather
than every package installed in the author's broader research environments.
The dependency solves were dry-run verified for both `osx-arm64` and `linux-64`.

## Use

```text
Use $protein-eval-skill to evaluate <evaluation-directory>. The native structures are stored in <native-directory>. Audit the files first, ask me about unresolved chain roles or mappings, then run the batch.
```

The skill audits before execution and asks for unresolved biological roles, assemblies, or chain mappings rather than guessing them.

Each executed batch also writes `results/method_summary.md` and
`results/method_summary.json`. The final Codex reply includes Folding,
Docking, and supplemental summary tables generated from those files. By
default, the Docking table reports the mean per-complex fraction of
target-binder interfaces satisfying strict `DockQ > 0.23` and the mean
per-complex fraction of binder groups satisfying
`target-aligned binder backbone RMSD < 2 Å`. Use
`--dockq-threshold` and `--binder-rmsd-threshold-angstrom` to change those
fingerprinted cutoffs for a batch. The Folding table likewise reports strict
`target self-aligned backbone RMSD < 2 Å` and
`binder self-aligned backbone RMSD < 2 Å` per-complex fractions. Change these with
`--target-self-aligned-rmsd-threshold-angstrom` and
`--binder-self-aligned-rmsd-threshold-angstrom`.

The role-scoped scoring update is documented in
[`VERSION_UPDATE_2026-11-11.md`](VERSION_UPDATE_2026-11-11.md). It changes
within-complex metric definitions while retaining the previous dataset-level
means, medians, and residue-pooled chirality aggregation.

The dataset aggregation update is documented in
[`VERSION_UPDATE_2026-11-11_v0.7.0.md`](VERSION_UPDATE_2026-11-11_v0.7.0.md).
For binder RMSD and target-binder iRMSD, the method-level median now uses one
mean per prediction. Binder RMSD threshold success is likewise averaged by
prediction. Chirality remains residue-pooled; the seven primary manuscript
figure metrics remain under `protein-eval-graph`.
